# 導入と接続

## 起動と接続

Windowsパッケージを展開し、中継サーバーを起動します。

```powershell
./tvt-remote-server.exe
```

Windowsでは通知領域にサーバーのアイコンが表示されます。アイコンを右クリックして「終了」を選ぶと、接続を閉じてサーバーを終了します。「設定」またはアイコンのダブルクリックで開く画面からも終了できます。通知領域が利用できない場合は、この画面を起動時に表示します。

起動時から状態画面を表示する場合は `--show-window` を指定します。通知領域のアイコンがある場合、状態画面の「×」は画面を閉じるだけで、サーバーは稼働を続けます。終了するときは「サーバーを終了」ボタンを使用してください。

コマンドから終了する場合は、起動中のサーバーと同じPC・ユーザーで次を実行します。

```powershell
./tvt-remote-server.exe --stop
```

`--pipe` を変更して起動したサーバーには、終了時も同じ `--pipe` を指定します。終了要求はローカルの名前付きパイプで処理します。通知領域のアイコンが不要な環境では `--no-tray` で起動し、`--stop` で終了できます。

PowerShellのスクリプトで終了完了を待ってから次の処理へ進む場合は、`Start-Process ./tvt-remote-server.exe -ArgumentList '--stop' -WindowStyle Hidden -Wait` を使用します。

### Windowsサインイン時の自動起動

通知領域のアイコンから「設定」を開き、「Windowsサインイン時に自動起動」にチェックを入れます。現在のユーザーだけを対象に、現在の実行ファイルと待受IP・ポート・IPC名を登録します。管理者権限は不要で、初期値はオフです。自動起動時は状態画面を開かず、通知領域へ常駐します。チェックを外すと登録を解除します。

サーバーを「終了」しても自動起動の登録は保持します。自動起動を止める場合はチェックを外してください。既に登録済みで新版を起動した場合は、登録先を起動した実行ファイルの場所と現在の待受設定へ更新します。フォルダを移動した場合も、新しい場所から一度起動してください。

登録にはユーザーの `HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run` を使用します。IPC名ごとに別の登録を管理します。登録コマンドがWindowsの260文字制限を超える場合は画面にエラーを表示します。[WindowsのRunキー仕様](https://learn.microsoft.com/windows/win32/setupapi/run-and-runonce-registry-keys)

### 待受アドレスと起動オプション

既定は `0.0.0.0:18765`、IPC名は `TVTDataBroadcastingRemote-v1` です。特定のIP・ポートを指定することもできます。

```powershell
./tvt-remote-server.exe --address 192.168.1.10 --port 18765
```

### 待受ポートの変更

サーバーの状態画面で「待受ポート」を1～65535の範囲で入力し、「適用」を押します。新しいポートの確保と設定保存に成功してから待受を切り替えます。使用中のポートや保存失敗の場合はエラーを表示し、元のポートで稼働を続けます。TVTestプラグインの接続は維持しますが、スマートフォンなどのリモコン接続は切断します。アプリの歯車から接続URLのポートも変更してください。

設定は現在のユーザー・IPC名ごとに保存し、次回起動時に使用します。`--port` を明示した場合は保存値より優先し、`--port 0` は従来どおり一時的な自動割り当てです。自動起動を有効にしている場合は、登録済みの起動引数も新しいポートへ更新します。

### リモコンアプリの接続

AndroidアプリまたはWindows版 `tvt-remote.exe` の接続設定に `ws://PCのLAN内IP:18765` を入力し、一覧から操作するTVTestを選びます。

必要に応じてWindowsファイアウォールでプライベートネットワークからの接続を許可してください。

0.3.0から、保存済みURLへ起動時・復帰時に自動接続します。初回だけ接続設定を開き、以降は毎回設定画面を表示しません。歯車の「起動・復帰時に自動接続」で無効化できます。

バックグラウンドへ移行すると接続と操作権を解放し、復帰時には再接続します。0.4.0から、プラグインに保存した操作先識別トークン `RemoteTargetToken` で前回のTVTestを探します。TVTestや中継サーバーが再起動して接続IDが変わっても、同じトークンの操作先が1つだけで空いていれば自動で操作権を取り直します。アプリを表示したままTVTestを再起動した場合も復帰します。キー操作は再送しません。

トークンはLANクライアントに公開する識別用の値で、認証・接続制限には使いません。未設定ならプラグインがUUIDを生成してINIに保存します。プラグイン設定画面の「リモコンの操作先識別トークン」、またはINIで半角英数字と `. _ -` の1～64文字に設定できます。大文字小文字は区別します。複数のTVTestには異なる値を設定してください。同じINIを共有する同時起動や、INIをコピーして同じ値にした場合は重複するため、自動選択を止めて重複を表示します。手動選択は可能です。

他のリモコンが使用中の操作権は取得しません。トークンを変更した場合はアプリで選び直してください。旧プラグインのようにトークンがない場合は従来の接続IDで復元し、TVTest再起動後は手動選択が必要です。

手動の「切断」はその起動中は維持します。「操作権を解放」を押した場合は記憶した操作先も解除し、復帰時に勝手に選び直しません。

## TVTest側

操作先識別トークンに対応する **TVTDataBroadcastingWV2** プラグインが必要です。

```ini
[TVTDataBroadcastingWV2]
EnableRemoteBridge=1
RemoteName=リビング
RemoteTargetToken=living-room
RemotePipeName=TVTDataBroadcastingRemote-v1
```

各TVTestに違う名前と識別トークンを付けてください。接続機能の有効化とパイプ名はTVTest起動時に読みます。識別トークンの変更は約1秒で反映します。サーバーの `--pipe` を変更する場合は `RemotePipeName` も合わせます。プラグインの接続機能は既定で無効です。

プラグインの表示機能が無効でも登録を維持し、dボタンで有効化できます。プラグイン自身はネットワークのポートを開きません。接続SDKは [`sdk/`](../sdk/) からプラグインの `remote/` へコピーして管理し、Qtをプラグインへリンクしません。
